# Browser-local agenda demo

The current delivery is explicitly a demo. `/demo.html` implements booking, rescheduling, cancellation, mock administration, appointment entry, blocks/unblocks and reset using only the browser's dedicated `labarberia:demo:v1` storage key. The homepage links to it. The existing production agenda, authenticated identity flow and D1 data remain separate and unchanged.

The service prices/durations and booking rules match the approved business catalog. Availability, appointments, professional display names and the Dueño/Jonathan administrator personas are unmistakably simulated. There are no personal-data fields, real account grants, customer messages, payment, production API requests or new dependencies. Each browser has its own demo; it is not a shared multi-user calendar or an authorization system.

The pure demo store validates bounded synthetic-only records, handles malformed/denied storage, preserves reloads when storage is available, rejects overlaps and stale versions, and reports cross-tab changes. External storage changes invalidate open edit/confirmation dialogs before refreshing, preventing an old action from affecting a replacement example after reset. Browser storage is not presented as production security or atomic multi-user persistence.

The new page has no previous application screenshot to compare: it did not exist in Site v10. Actual starting, completed, administrative and enlarged-text screenshots plus real flow videos are produced by exact-head CI. Source tests and browser tests prove this limited demo scope, not hosted production identity, backup/recovery or performance acceptance. The separately paused performance task is untouched.
